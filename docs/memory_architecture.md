# AI 分层长短期记忆体系架构与工程落地规范 (Memory Architecture & Engineering Guide)

本文档系统阐述在现代大模型应用与智能体（Agent）工程体系中，**短期记忆 (Working Memory)** 与 **长期记忆 (Long-term Memory)** 的运作机理、存储介质选型以及在本工程中的落地规范。

---

## 🏗️ 一、AI 四层应用架构与记忆映射

计算机软硬件系统有 CPU 寄存器、L1/L2/L3 缓存、内存条与硬盘的层级分工；AI 智能体体系同样具备清晰的四层应用架构：

```text
┌───────────────────────────────────────────────────────────────┐
│  L1. 基座模型层 (Model Layer)                                  │
│  - 静态权重参数 (Parametric Memory)                           │
│  - 特点：预训练固化，只读，无法在线即时单点改写                  │
└──────────────────────────────┬────────────────────────────────┘
                               │ Prompt 注入与上下文喂入
┌──────────────────────────────▼────────────────────────────────┐
│  L2. 运行时上下文层 (Runtime & Context Layer)                  │
│  - Context Window (上下文窗口) 与 KV Cache 硬件显存            │
│  - 瞬时感官记忆 (Sensory Buffer)：单次推理时短暂保留            │
└──────────────────────────────┬────────────────────────────────┘
                               │ 状态机与工作流调度
┌──────────────────────────────▼────────────────────────────────┐
│  L3. 智能体编排层 (Agent & Workflow Layer)                     │
│  - 【短期工作记忆 (Working Memory)】                           │
│  - 会话级状态机：工单意图锚定、Todo 步骤追踪、原生图形置顶卡片    │
│  - 生命周期：随当前会话启动而建立，随会话关闭/归卷而结算        │
└──────────────────────────────┬────────────────────────────────┘
                               │ 归卷沉淀 ➔ 提取持久化 ➔ 开箱自检召回
┌──────────────────────────────▼────────────────────────────────┐
│  L4. 外部持久存储层 (Storage & Knowledge Layer)                │
│  - 【长期持久记忆 (Long-term Memory)】                         │
│  - 跨会话脑库：偏好画像 (Context)、实战避坑 (Lessons)、台账    │
│  - 物理介质：本地 Markdown 文件库、Git 审计链、向量库、SQLite   │
└───────────────────────────────────────────────────────────────┘
```

## ⚡ 二、短期工作记忆 (Working Memory)

### 1. 概念定位
短期记忆是智能体在**处理当前单个会话或具体任务时的“桌面工作台”**，负责维持当前任务的连贯性、执行专注度与步骤状态。

### 2. 四大核心使用机制
1. **意图锚定 (Goal Pinning)**：
   - 收到任务后，在首轮【定标】阶段提炼出确定性的工单，并使用 `./scripts/rename_session.sh` 锁定 8 字会话标题；
   - 标题与工单在整个生命周期内固定不变，防止多轮执行发生“目标漂移”。
2. **步骤流转维持 (Step Progression)**：
   - 使用 `todo_write` 维护全局任务清单；
   - 遵循“单一在办事项”原则：同一时刻仅允许一个步骤处于 `in_progress`，完成一项勾选一项。
3. **视口聚焦组件 (Viewport Focus)**：
   - 采用 DSH 原生图形化引用区块（Blockquote），在当前交互视口常显核心结论与进度状态。
4. **上下文动态压缩 (Context Compaction)**：
   - 当交互轮次过多或工具输出过长导致逼近 Token 上限时，智能体自主对过往工具输出进行意图提炼，保留结论、丢弃冗余原始数据。

### 3. 存储载体与介质
- **进程内存 State**：智能体运行时的局部变量与调用栈；
- **会话持久流**：宿主底层自动将每轮事件流追加写入 `session.jsonl.zstd`；
- **硬件显存**：注意力机制的 KV Cache。

## 🧠 三、长期持久记忆 (Long-term Memory)

### 1. 概念定位
长期记忆是**跨会话、跨任务、跨周期的“终身大脑”**。它使得智能体在换了新会话、关机重启或面对全新任务时，依然保留历史沉淀下来的经验与偏好。

### 2. 长期记忆的三大核心板块
1. **用户偏好画像记忆 (User Profile & Preference Memory)**：
   - 存储路径：`memory/context_memory.md`；
   - 内容：用户的工作习惯（全中文、通俗直白大白话）、界面排版要求（禁止裸 HTML、8 字命名）。
2. **实战避坑与情景经验记忆 (Episodic & Lessons Memory)**：
   - 存储路径：`memory/lessons_learned.md`；
   - 内容：历史上踩坑排查出来的隐性机制（如 `session.rename` RPC 接口调用、图片浏览 settings 放行、原生 Markdown 引用色条）。
3. **规则与需求溯源记忆 (Semantic & Ledger Memory)**：
   - 存储路径：`rules/*` 与 `docs/requirements.md`；
   - 内容：系统最高元规则、标准工作流与 REQ 需求演进轨迹。

### 3. 存储介质选型对比

| 存储介质 | 适用场景 | 优点 | 缺点 | 本工程选型建议 |
| :--- | :--- | :--- | :--- | :--- |
| **纯文本 Markdown 文件** | 核心规则、偏好约定、避坑经验、需求台账 | 透明直观、人机共读、天然支持 Git 版本追溯与回滚 | 海量数据检索性能受限 | **首要核心介质**（100% 采用） |
| **嵌入式全文本库 (SQLite/FTS)** | 历史会长文本会话全量检索 | 支持毫秒级全文模糊匹配，单文件易备份 | 不具备语义近似联想能力 | 备选（后续有数万条历史会话时启用） |
| **向量数据库 (Vector DB)** | 海量文档问答、非结构化知识匹配 | 支持语义模糊召回（KNN/余弦相似度） | 依赖 Embedding 模型，容易语义幻觉 | 复杂外挂大知识库时选配 |

## 🔄 四、长短期记忆流转与自愈闭环流程

长短期记忆不是孤立存在的，而是通过标准工作流形成动态闭环：

```text
[新任务启动]
     │
     ▼
1. 记忆读取 (Recall)  ─── 开箱自检六步法读取 memory/ 目录，继承偏好与避坑规则
     │
     ▼
2. 短期装载 (Load)    ─── 首轮定标，工单注入当前上下文，Todo 清单初始化
     │
     ▼
3. 任务攻坚 (Exec)    ─── 在短期记忆维持下分步推进，排查新问题
     │
     ▼
4. 经验提炼 (Extract) ─── 攻坚中发现的新机制、新避坑点，提炼为通用知识
     │
     ▼
5. 长期回写 (Consolidate) ── 收尾归卷，回写至 memory/ 与 docs/requirements.md
     │
     ▼
6. 版本入库 (Commit)  ─── Git 语义化提交推送到远程，永久沉淀
```

## 📋 五、工程实施守则

1. **先查后做**：任何新任务第一步必须查阅 `memory/lessons_learned.md`，杜绝重复犯已经排查解决过的低级错误；
2. **有变必录**：只要在任务执行中排查出了环境新机制（如新 API、新门禁、前端特性），必须在归卷阶段同步写入 `memory/`；
3. **单一权威**：同一类偏好或规则只在一处定义，增量更新采用归并演进，保持长期记忆干净整洁。
