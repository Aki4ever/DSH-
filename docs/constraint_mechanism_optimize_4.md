## 一、原始需求（用户口语原文）

> 以下为优化管控机制
> 0、每次执行任务都要约束好输入和输出（由你自己去约束规划），确保不会出现废话太多的情况；
> 1、如图 1，任务控件的后面都跟一个实时同步的进度；然后任务首栏有一个整体任务的进度；
> 2、bash、think 这些后面全部都要输出中文；
> 3、保证每次输出的内容足够精简（尽量在一个展示页面内输出完），不要过多废话（如果是一些废话，就要用小字说明表达不是主要问题），要足够聚焦任务的输出；
> 4、能不重启就不重启，实在不行再重启。

**用户拍板补充（本会话问答）**：
- 改动范围：**A. 现在就改内置包**（并已选择把 App 复制到 `/Applications` 以取得可写安装位）；
- 进度口径：**A. 完成数 / 总数，进行中按半步计**；
- 中文化深度：**A. 界面标签 + 我的回复正文同时中文化**。

## 二、整理后的可执行需求

### 2.1 一句话定义

**看板要能一眼看出"到哪一步了"，回答要能一页看完——进度可见、废话归零、少重启。**

### 2.2 五条可机械判定的诉求

| # | 诉求 | 具体做什么 | 验收（可机械判定） |
| :-- | :--- | :--- | :--- |
| **Q1** | **每行实时进度** | `TodoPanel` 每行在任务名后加「状态 + 迷你进度条 + 百分比」 | 展开看板时 7 行每行都有进度；状态变化后该行进度随之变化 |
| **Q2** | **首栏总进度** | 标题栏加「总进度条 + `N%（已完成/总数）`」 | 标题栏出现进度条；2 完成 + 1 进行中 / 7 项 = **36%** |
| **Q3** | **界面标签全中文** | `Think`→`思考中`；`Search/Read/Bash/Write/Edit/Code/Tool call`→`搜索/读取/执行命令/写入/编辑/代码/工具调用` | 会话流中不再出现这些英文标签 |
| **Q4** | **输出精简 + 中文化正文** | 每轮输出：结论前置、单页内、废话用小字（`<sub>`）；工具名/状态一律中文 | 回复中英文标签出现次数为 0；主要结论在一屏内 |
| **Q5** | **能不重启就不重启** | 首选"刷新页面 / HMR / 脚本热改"；确需重启必须给出物理原因 | 本次仅因"运行时在只读 DMG 上"重启 1 次，且重启前已一次性把补丁做完 |

### 2.3 输入输出约束（需求 0 · 由我自定并逐轮执行）

| 维度 | 硬约束 |
| :--- | :--- |
| **任务输入** | 开工先改名 → 查门禁 → 只接收"本次要做的范围"，不擅自扩张；范围外的一律记入待办而不动手 |
| **交付输出** | 每轮必须给：①做了什么（结论前置）②改了哪些文件（行内代码）③未验证项 |
| **篇幅上限** | 正文 ≤ 1 屏（约 40 行 / 1200 字）；工具调用单次输出 ≤ 40 行；表格 > 长段落 |
| **失败表达** | 被拒绝/失败必须给出：现象 + 命令 + 退出码，不复述过程 |
| **废话处置** | 次要信息一律 `<sub>` 小字，且不得占正文位置 |

## 三、实现方案（已落地部分）

| 层 | 落点 | 说明 |
| :--- | :--- | :--- |
| 界面 | `dsh-client-ui-conversation/lib/client.js` | 加 `todoPercent()`（完成 + 进行中×0.5）/ `itemPercent()` / `itemStateText()`；标题栏插入 `.bar` 进度条；每行插入 `.itemProgress`（状态字 + 36px 迷你条）；追加 `.lXshSW_bar*` 样式 |
| 界面 | `dsh-client-ui-tool/lib/client.js` | `VARIANT_TITLES` 七个英文设计字面量中文化 |
| 界面 | `dsh-client-ui-conversation/lib/client.js` | 推理行 `title: "Think"` → `"思考中"` |
| 工具 | `scripts/patch_dsh_todo_progress.cjs` | 幂等补丁器（锚点唯一性校验 + 自动备份 + 回读校验 + 只读卷保护）；`--check` 退出码 1 表示补丁缺失 |

**为什么用补丁而不是源码改动**：本机 DSH 是**桌面发行版**，规则库不是 DSH 源码仓，前端以成品包形式随 App 分发（宿主直接把这些 `client.js` 作为浏览器模块服务）。因此只能做"幂等 + 可校验 + 可回滚"的成品包补丁；**App 升级覆盖后重跑一次脚本即可**。

## 四、技术事实（实测，非推测）

1. **看板就是 `TodoPanel`**：装在 `conversation.input.dock`（`order=0`），仅 `todos.length === 0` 时不渲染；
2. **数据没有数字进度**：`todos` 投影只有 `content` + `status`（`pending` / `in_progress` / `completed`），所以进度只能由状态派生 → 口径定为"完成 + 进行中×0.5"；
3. **改完不用重启 App**：宿主 index.html 的 boot 图里每个插件带 `?rev=<哈希>`，改文件后**刷新页面**即换新 rev；
4. **英文标签是硬编码字面量**，不在语言包里：`Think`（`ui-conversation` L9418）与 `VARIANT_TITLES`（`ui-tool` L21-28）；
5. **当前 App 跑在只读 DMG 上**：`/dev/disk17s1 on /Volumes/DSH Desktop (apfs, read-only)`，实测写入报 `EROFS`；
   → 一次性安装动作：`ditto` 复制到 `/Applications/DSH Desktop.app`，补丁打在副本上，**仅此一次需要重启**；
6. **签名影响**：原包为 Developer ID 签名（`H8MSV8BL2G`）且无特殊 entitlements，改动后需 ad-hoc 重签，否则 macOS 可能拒绝启动。

## 五、验收标准

- [ ] `node scripts/patch_dsh_todo_progress.cjs --check` 退出码 0（六项回读校验全绿）；
- [ ] 看板标题栏可见总进度条与 `N%（已完成/总数）`；口径可复算（2 完成 + 1 进行中 / 7 = 36%）；
- [ ] 每一行任务后可见「状态 + 迷你进度条」；
- [ ] 会话流中不再出现 `Think` / `Bash` / `Search` / `Read` / `Write` / `Edit` / `Code` / `Tool call`；
- [ ] 全程仅重启 1 次，且重启原因是"只读 DMG 无法写入"这一物理限制；
- [ ] 双检脚本（冗余 / 冲突 / 存量）通过，台账与总版本同步推进。
