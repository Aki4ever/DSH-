# 全局需求管理台账 (Requirements Ledger)

本文档为项目的**独立核心需求文档**。依据项目全局元规则，所有规则的生命周期（新增、优化、废弃）必须在此文档中同步记录，杜绝无需求对应的规则变更。

---

## 📌 需求生命周期与状态定义

| 状态 | 标识 | 说明 |
| :--- | :--- | :--- |
| **生效中** | `[ACTIVE]` | 需求已确认，且对应规则已在规则库中落实生效 |
| **演进中** | `[EVOLVING]` | 需求正在经历版本迭代或优化调整 |
| **已废弃** | `[DEPRECATED]` | 原需求已失效或被新需求替代，仅保留历史追溯 |

---

## 🛡️ 智能查重与过滤准则 (De-duplication Policy)

任何新需求录入或规则变更前，必须依次进行以下核验：
1. **字面与关键词核验**：对比现有需求条目的核心关键字；
2. **意图与语义核验**：若新提出的诉求与已有条目目标一致（例如换种句式重复同一限制），**严禁新建条目**；
3. **处置动作**：
   - **完全重复**：直接拦截并丢弃，不增加冗余记录；
   - **增量优化**：在原有需求条目下追加“优化变更记录”，状态更新为 `[EVOLVING]`；
   - **全新诉求**：分配唯一自增编号（`REQ-xxx`），录入台账。
