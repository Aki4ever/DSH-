> - **生效状态**：`[Release 稳定生效]`

本文档回答唯一一个问题：**智能体的一次回复应当长成什么样**。
它是该问题的**唯一权威源**；`AGENTS.md`、元规则、技能契约、脚本注释一律只允许写**指针**，禁止复述本文的格式定义
（同一事实写两处，改一处必漏一处 —— 本工程已有实测教训）。

> 📌 **边界声明（先说清不判什么）**：本契约只判**结构与可读性**，**不评价内容好坏、不度量语义质量**。
> 任何"讲得对不对"的打分都会退化成模型自说自话；能被机器守住的，只有形状与字数。

## 一、一句话总纲

**一次合格回复 = 首行状态徽标 → 一句话总结 → 分层正文 → 进度回执 → 文末五联装。**

五个位置各司其职，顺序固定，缺一即不合格：

| 序 | 位置 | 作用 | 判定性质 |
| :--: | :--- | :--- | :--- |
| ① | 首行状态徽标 | 一眼看清现在是规划 / 实施 / 进行中 / 受阻 | **硬判据** |
| ② | 一句话总结 | 首屏零击直达结论，不用往下翻 | **硬判据** |
| ③ | 分层正文 | 抬头分级、缩进成套、空行断句，扫一眼就懂结构 | 硬判据 + 报告项 |
| ④ | 进度回执 | 说清做到哪一步、凭什么这么说、还差什么 | **硬判据** |
| ⑤ | 文末五联装 | 收尾固定五项（定义见元规则第三十四条，本文不复述） | **硬判据** |

---

## 二、五个位置的细则

### ① 首行状态徽标（硬判据）

- **位置**：正文的**第一个非空行**，不得有前言、寒暄或铺垫；
- **取值**：必须且只能含下列四态图标之一，并紧跟中文状态词：

| 图标 | 状态词 | 什么时候用 |
| :--: | :--- | :--- |
| 🟡 | 【方案规划态】 | 只分析、只出文案，**没有任何文件改动** |
| 🟢 | 【实施完成态】 | 已写入、已过门禁、已推送 |
| 🔵 | 【正在执行态】 | 复合长任务推进中，本轮只走了一段 |
| 🔴 | 【阻断受阻态】 | 遇不可抗力暂停，须说清卡在哪 |

- **允许的包装**：可加粗、可加 `> ` 引用、可与标题同行，只要**图标出现在第一个非空行**即可；
- **为什么必须是硬判据**：状态靠自述时，用户永远分不清"我打算做"和"我已经做了"。

### ② 一句话总结（硬判据）

- **标签**：`一句话总结`（允许加粗为 `**一句话总结**`，允许写成 `## 一句话总结` 小标题）；
- **位置**：必须出现在正文**前 6 个非空行之内**（首屏范围内）；
- **字数**：正文汉字数 **4 ~ 30 个**（数字、字母、标点不计入）；
- **写法**：说**结论**，不说过程；不铺垫、不解释、不问候；
- **例外**：极短回复（正文整体不足 40 个汉字）可豁免本项 —— 此时首行状态徽标本身已承载结论。

### ③ 分层正文（2 条硬判据 + 3 项报告项）

**抬头（章节标题）**

- 只用 `#` / `##` / `###`，最多 **3 级**（`#` 记 1 级，故最深只写到 `###`；与可读性法典"嵌套严禁超过 3 级"同源）；
- **禁止跳级**：从 `##` 直接跳到 `####` 属于跳级（硬判据）；`##` 的下一个标题最多只能是 `###`；
- **为什么禁跳级**：跳级会让阅读器与目录树都断链，读者无法判断层级关系。

**缩进（列表与续行）**

- 列表最多嵌套 **3 层**（硬判据）；每层缩进 2 个空格；
- 续行与所在层级的文字左对齐，不悬挂；
- 表格、代码块内不适用缩进规则。

**空行（报告项）**

- 章节标题**前**留 1 个空行、**后**留 1 个空行；
- 段落之间留 1 个空行；
- 禁止连续 3 个及以上空行；
- **为什么只是报告项**：Markdown 渲染器对空行的容忍度不同，本地无法客观判定"渲染后是否粘连"。

**扫视友好（报告项）**

- 善用标题 / 表格 / 列表作为视觉锚点；
- 粗体只用于关键词，严禁全篇加粗；
- 单行建议 45~75 个汉字。

### ④ 进度回执（硬判据，即"反馈层"）

- **位置**：正文末尾、**文末五联装之前**，是独立卡片，**不算入五联装**；
- **五行固定字段**（标头文字必须逐字出现）：

| 字段标头 | 写什么 |
| :--- | :--- |
| `🔧 本轮做了什么` | 落到磁盘的实体动作（文件 / 命令），不写心理活动 |
| `🏷️ 需求版本` | 本次改动所依据的需求条目版本号，如 `REQ-092 · v1.0.0`（REQ-092 / R2-a 新增） |
| `🧪 判定证据` | 判定命令 + 真实退出码，**没跑过不许写** |
| `📊 完成度` | 叶子级 `x/y`（如 `R1 3/4`），数字由台账实跑取 |
| `🚧 还差什么` | 未完成项如实列出；没有就写"无" |

- **为什么新增「需求版本」**：用户要求"输出结构新增一项：需求版本号"。它必须是**硬判据**——
  版本号是枚举式取值，"对得上/对不上"是确定性事实，且要与机读台账
  [`ai-control/requirements/req_versions.json`](../../ai-control/requirements/req_versions.json) 对拍，
  判定入口 `node scripts/req_version_audit.mjs --check`；只写"见台账"而不同时披露版本号，判红。
- **数字不许手写**：完成度与证据必须能由 `node scripts/progress_ledger.mjs report --json` 复算出来，
  判定器会做**对拍**；手写一个对不上的数字即判红；
- **为什么要有它**：进度历来靠"我说我做了"，没有任何东西能证伪。回执把"做了什么"降为可核对的物理事实。

### ⑤ 文末五联装

- **唯一权威定义**：`rules/system/meta_rules.md` **第三十四条**；
- 本文**不复述**其五项内容，只声明**位置关系**：五联装必须是整条回复的**最后 5 项**，进度回执在其之前；
- 违反位置关系（例如五联装后面又追加内容）视为结构不合格。

## 三、双档输出（浅白档 / 专业档）

### 1. 档位定义

| 档位 | 面向谁 | 写法 | 何时启用 |
| :--- | :--- | :--- | :--- |
| **浅白档（默认）** | 普通用户 | 大白话讲透；专业词首次出现必须随文解释；复杂机制换生活化比喻 | **不声明就是它** |
| **专业档** | 有对应专业知识的人 | 术语直接用、实现细节可展开、给参数与命令原样 | 用户**显式要求**才切 |

### 2. 切换开关（显式说明才算数）

- **触发词**（用户侧，任一命中即切换）：`专业档` / `专业版` / `面向专业人士` / `详细技术版` / `技术细节版`；
- **输出侧标记**（硬判据）：切到专业档时，**必须**在正文前 6 个非空行内置入唯一标记 `⚙️ 专业档`；
- **默认判定**：没有该标记即**按浅白档判**，不存在"没说清所以随便写"的中间态；
- **禁止**：同一回复里两档混说（前文大白话、后文突然甩术语且不解释）。

### 3. 浅白档的硬约束

- 专业术语**首次出现必须解释**：用括号注释、破折号补充或"也就是说"接一句大白话；
- 复杂机制**优先打比方**：现成比喻库见 [`skills/plain-analogy-explanation/SKILL.md`](../../skills/plain-analogy-explanation/SKILL.md)（乐高积木 / 安检门 / 字典目录 / 红绿灯）；
- **判定**：术语密度（命中黑话词表且同行无解释标记）为**报告项**，
  因为"哪些词算黑话"没有外部权威边界，把它当硬门等于**自行发明阈值**。

### 4. 专业档不变的部分

切专业档**不等于**可以写长、写乱、跳过结构：`① ~ ⑤` 五个位置与全部字数约束**照旧生效**。

## 五、判定入口（可跑命令，退出码即结论）

| 判定内容 | 命令 | 退出码语义 |
| :--- | :--- | :--- |
| 字数 / 行数 / 五联装 | `node scripts/output_audit.mjs --check` | 0 达标 · 1 不达标 · 2 取不到证据（**绝不算通过**） |
| ① 首行徽标 · ② 一句话总结 · ③ 层级与缩进 · ④ 进度回执 · ③⑤ 档位标记 | 同上（并入同一判定器，不另起一套） | 同上 |
| 生僻字 | `node scripts/language_audit.mjs --check` | 0 无生僻字 · 1 命中 · 2 取不到证据 |
| 判定器自身的可信度 | `node scripts/output_audit.mjs --self-test` · `node scripts/language_audit.mjs --self-test` | 0 反向用例全部判红成功 |

> **反例前置**：两个判定器都必须先证明"该红的能判红"（注入违规样本 → 必须退出码 1），
> 否则它们只是一盏永远亮着的绿灯。

## 六、阈值登记（唯一调参入口）

所有数字边界登记在 [`ai-control/config/gates.conf`](../../ai-control/config/gates.conf) 的 `OUT_*` 段，改完即时生效：

| 配置项 | 含义 | 默认 |
| :--- | :--- | :---: |
| `OUT_BANNER_ICONS` | 允许的首行状态图标 | `🟡 🟢 🔵 🔴` |
| `OUT_SUMMARY_LABEL` | 一句话总结的标签文字 | `一句话总结` |
| `OUT_SUMMARY_SCAN_LINES` | 一句话总结必须出现在前几个非空行内 | `6` |
| `OUT_SUMMARY_MIN_CHARS` / `OUT_SUMMARY_MAX_CHARS` | 一句话总结汉字数区间 | `4` / `30` |
| `OUT_SUMMARY_EXEMPT_BODY_CHARS` | 正文短于此值豁免一句话总结 | `40` |
| `OUT_MAX_HEADING_DEPTH` | 最大标题嵌套级数 | `3` |
| `OUT_MAX_LIST_DEPTH` | 最大列表缩进层数 | `3` |
| `OUT_PRO_ICON` | 专业档标记 | `⚙️ 专业档` |
| `OUT_RECEIPT_FIELDS` | 进度回执必须逐字出现的字段标头（含 `🏷️ 需求版本`） | 五项，见 `gates.conf` |

> **为什么阈值必须外置**：写死在脚本里的数字，会让"规范"与"判定"各说各话；
> 外置到唯一调参文件后，改阈值不需要动代码，也不会漏改。
