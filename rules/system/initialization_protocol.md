# 项目与目录结构化初始化协议 (Initialization Protocol)

本协议对“项目开启时的首步初始化”以及“新建文件夹后的一键初始化”进行结构化定义，保证工程始终井井有条、开箱即用。

---

## 🚀 一、会话级/项目级自检初始化（每次开启任务的第一步）

每当智能体开始新的对话、打开项目或处理任务时，**第一步操作必须执行“开箱自检六步法”**：

```text
[打开项目/开启会话]
       │
       ▼
1. 检查运行权限 ─── 确认当前沙箱读写权限与审批策略（如无弹窗审批，需自律防破坏）
       │
       ▼
2. 载入最高规则 ─── 读取 meta_rules.md，明确元规则、红线、通俗语言与执行双轨分流
       │
       ▼
3. 查看需求台账 ─── 检索 docs/requirements.md，掌握正在演进中的需求与历史状态
       │
       ▼
4. 检索知识记忆 ─── 读取 memory/ 目录（沉淀经验与避坑要点，继承上下文）
       │
       ▼
5. 明确分流路径 ─── 判定任务难度分值（≤35分轻量流 ｜ >35分标准完备六步流）
       │
       ▼
6. 核对版本状态 ─── 检查 Git 状态是否干净，确认基准分支（main）
```

### ⚡ 强制执行契约
- 遇新任务必须定标打分，在首轮交互中立刻调用 `./scripts/rename_session.sh` 重命名锁定会话；
- 简单任务（≤35分）执行【探➔攻➔归】三步速结，复杂任务（>35分）严格执行标准六步闭环并开启吸顶置顶组件。

## 📁 二、目录级一键初始化（新建文件夹后的一键标准动作）

当新建一个文件夹后，只需输入一句初始化指令（例如：`初始化 <目录路径>` 或新建后直接说 `初始化`），智能体将自动完成以下**四件套标准化工作**：

### 自动化四件套标准
1. **建立占位防丢文件**：在新建目录下创建 `.gitkeep`，防止空目录在 Git 同步时被忽略；
2. **生成目录专属说明**：在目录下自动创建 `README.md`，使用统一规范模板（说明该目录作用、文件分类与命名要求）；
3. **登记根目录索引**：将新目录自动追加到根目录 `README.md` 的“目录结构说明”树中；
4. **Git 纳入版本管理**：执行 `git add` 将新目录结构放入暂存区。

## 💻 五、项目立项必出 CLI 规划（REQ-097 / R4）

**为什么单列一条**：AI 能不能用上这个项目，不取决于它写了多少文档，而取决于**有没有一条能跑的命令**。
实测（2026-10-02）：本协议全文 0 处提到 CLI，初始化脚本只建目录与台账——"项目开启时把 CLI 规划进去"
一直是句**没有载体的口号**。

### 1. 立项必做（做完才算初始化完成）

1. **产出清单**：项目根生成 `CLI_PLAN.md`（模板见 [`templates/cli_plan_template.md`](../../templates/cli_plan_template.md)，也接受 `docs/cli_plan.md`）；
2. **至少一条真命令**：清单里写出至少一条**真能跑**的命令（写示例占位等于没写，会被判红）；
3. **接口契约在位**：每个能力配一份接口契约（目录型 `<单元>/interface.json`，文件型 `scripts/interfaces/<脚本名>.interface.json`），字段口径见 [`knowledge/common/execution_layer_interface_spec.md`](../../knowledge/common/execution_layer_interface_spec.md)；
4. **登记进索引**：能力登记进本项目的索引文件，方便 AI 检索。

### 2. 自动化入口与判定

| 动作 | 命令 |
| :--- | :--- |
| 新工程脚手架（自动生成 `CLI_PLAN.md`） | `bash scripts/init_project.sh <项目路径> [项目名] [描述]` |
| 判定（本工程 / 指定工程） | `node scripts/cli_plan_audit.mjs --check` · `node scripts/cli_plan_audit.mjs --project <路径>` |
| 反向自证（缺清单 / 命令悬空 / 契约悬空必须判红） | `node scripts/cli_plan_audit.mjs --selftest` |

退出码：`0` 三条全过 · `1` 存在不达标 · `2` 取不到证据（**2 绝不算通过**，遵循元规则第三十六条）。

> **清单不是文档摆设**：判定器逐条核对清单里的命令与契约路径是否真实存在——写了跑不起来的、留下死行的，一律判红。
