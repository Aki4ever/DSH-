# 项目与目录结构化初始化协议 (Initialization Protocol)

本协议对“项目开启时的首步初始化”以及“新建文件夹后的一键初始化”进行结构化定义，保证工程始终井井有条、开箱即用。

---

## 🚀 一、会话级/项目级自检初始化（每次开启任务的第一步）

每当智能体开始新的对话、打开项目或处理任务时，**第一步操作必须执行“开箱自检六步法”**：

```text
[打开项目/开启会话]
       │
       ▼
1. 检查运行权限 ─── 确认当前沙箱读写权限与审批策略（如无弹窗审批，需自律防破坏）
       │
       ▼
2. 载入最高规则 ─── 读取 meta_rules.md，明确元规则、红线、通俗语言与执行双轨分流
       │
       ▼
3. 查看需求台账 ─── 检索 docs/requirements.md，掌握正在演进中的需求与历史状态
       │
       ▼
4. 检索知识记忆 ─── 读取 memory/ 目录（沉淀经验与避坑要点，继承上下文）
       │
       ▼
5. 明确分流路径 ─── 判定任务难度分值（≤35分轻量流 ｜ >35分标准完备六步流）
       │
       ▼
6. 核对版本状态 ─── 检查 Git 状态是否干净，确认基准分支（main）
```

### ⚡ 强制执行契约
- 遇新任务必须定标打分，在首轮交互中立刻调用 `./scripts/rename_session.sh` 重命名锁定会话；
- 简单任务（≤35分）执行【探➔攻➔归】三步速结，复杂任务（>35分）严格执行标准六步闭环并开启吸顶置顶组件。

---

## 📁 二、目录级一键初始化（新建文件夹后的一键标准动作）

当新建一个文件夹后，只需输入一句初始化指令（例如：`初始化 <目录路径>` 或新建后直接说 `初始化`），智能体将自动完成以下**四件套标准化工作**：

### 自动化四件套标准
1. **建立占位防丢文件**：在新建目录下创建 `.gitkeep`，防止空目录在 Git 同步时被忽略；
2. **生成目录专属说明**：在目录下自动创建 `README.md`，使用统一规范模板（说明该目录作用、文件分类与命名要求）；
3. **登记根目录索引**：将新目录自动追加到根目录 `README.md` 的“目录结构说明”树中；
4. **Git 纳入版本管理**：执行 `git add` 将新目录结构放入暂存区。

## 💬 三、快捷口令与触发方式

- **口令示例 1**：`初始化 rules/compliance`
- **口令示例 2**：用户刚新建了 `docs/manual/` 文件夹后，直接回复：“`初始化`”
- **执行效果**：无需用户繁琐指定每个文件，智能体自动调用标准模板建全全套说明与占位文件。
