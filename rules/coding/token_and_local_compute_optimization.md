# 本地运算优先与 Token 结构性降耗工程规范 (Local-Compute First & Token Optimization)

本文档是系统内降低 LLM Token 消耗、提升执行确定性与响应速度的**最高工程编码与执行规约**。核心原则是：**“该本地算的坚决在本地算，同等效果下只向模型输入浓缩的结构化数据”**。

## ⚡ 一、三大核心降耗支柱 (Three Pillars)

```text
┌───────────────────────────────────────────────────────────────┐
│                    大模型决策层 (LLM Context)                 │
│         只接收：精准命中的行切片、统计数字、浓缩 JSON          │
└──────────────────────────────▲────────────────────────────────┘
                               │ 极度精简传输 (降耗 70%~90%)
┌──────────────────────────────┴────────────────────────────────┐
│                    本地运算层 (Local Compute Engine)           │
│  (grep/ripgrep, node/python 统计脚本, 语法编译器, 缓存持久化)  │
└───────────────────────────────────────────────────────────────┘
```

### 1. 本地轻量计算优先 (Local-Compute First)
- **统计与度量**：行数统计、代码行覆盖率、文件大小、字符频次、哈希计算等确定性指标，**必须**使用本地命令（`wc -l`、`stat`、`shasum`、Node 脚本）计算，严禁让模型逐行阅读推算；
- **大规模过滤与正则匹配**：日志过滤、异常排查，先在本地用 `grep -n -C 3` 或脚本筛选出真实告警行，严禁将全量日志（>100行）吐给上下文；
- **语法校验与编译诊断**：代码语法是否通过，直接运行 `node --check`、`bash -n`、`python -m py_compile` 等，以退出码和单行报错为依据，严禁靠模型“肉眼 Lint”。

### 2. 精准上下文剪裁 (Targeted Context & Pruning)
- **禁止全盘盲读**：对超过 200 行的文件，严禁无参数直接 `read`；必须先通过 `grep -n` 获取目标关键词行号，随后以目标行为中心传 `offset` 和 `limit`（推荐 20~50 行）局部精准读入；
- **双层索引召回**：查询系统功能或规则时，必须先查轻量级索引卡（`indexes/shortcuts_index.md`、`indexes/capabilities_index.md`），仅在确实需要底层 Schema 时再向下穿透；
- **拒绝冗余长复述**：答复中禁止将已存在于上下文的大段代码或规则条文原样复述，应采用行号切片或行内代码指针引用。

### 3. 结果本地持久化与缓存复用 (Caching & State Memoization)
- **高频计算本地落盘**：门禁状态、依赖图谱、规则检测结果写入本地快照（如 `.dsh-control/status.json`）；
- **TTL 缓存秒回**：在有效生命周期（如 30 秒）内直接读取磁盘缓存，杜绝每一步操作都全盘重复扫描计算。

## 🚫 二、常见反模式与正向重构对照表 (Anti-Patterns vs Best Practices)

| 场景 | 🔴 高耗低效反模式 (严禁) | 🟢 本地运算高效模式 (推荐) | Token 节省预估 |
| :--- | :--- | :--- | :---: |
| **检索特定配置项** | 全量 `read` 1000 行的大配置文件 | `grep({ pattern: "target_key" })` 精准命中行号 | **90% ↓** |
| **代码语法排查** | 将整段 JS 代码贴进 prompt 问模型有无语法错误 | 本地运行 `node --check script.mjs`，看退出码 | **95% ↓** |
| **文件数量与目录健康度** | 递归全盘列出所有子文件由模型数数 | 本地运行 `./scripts/control_gates.sh check` 读统计指标 | **85% ↓** |
| **长日志异常追踪** | 全文读取 5000 行日志，让模型总结报错 | `grep -E -n "ERROR|FATAL" app.log` 提取关键片段 | **92% ↓** |
| **版本一致性对比** | 逐个打开所有文档，肉眼比对版本号 | 运行 `node scripts/legacy_align_scan.mjs` 读聚合差异 | **80% ↓** |

## 📏 三、度量与执行监督

1. **写后自检**：在进行大规模文件分析或批量修改前，自问“这步操作能否先用一行脚本在本地过滤”；
2. **审计留痕**：在 `memory/efficiency_audit_log.md` 追踪各任务的步骤与耗时，持续消灭无效冗长读取。
