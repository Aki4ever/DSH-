本文档确立了工程全域复杂与多阶段任务的**分层调度架构**：单例全局唯一并发编排中枢 **`Agent PP`** 与 短生命周期串行执行体 **`Agent Life(N)`** 的父子分工契约。

---

## 🏛️ 一、核心角色与单例铁律

```text
               ┌────────────────────────────────────────────────────────┐
               │              单例并发编排中枢: Agent PP (唯一)          │
               │   - 拓扑拆解: 将大任务拆解为可并行的子模块               │
               │   - 调度管控: 并行调度 life1, life2, life3...          │
               │   - 屏障汇聚: 等待所有分支完成，处理跨分支状态          │
               └────────────┬─────────────────────────────┬─────────────┘
                            │ 并行分派                    │ 并行分派
                            ▼                             ▼
       ┌───────────────────────────────┐  ┌───────────────────────────────┐
       │   短生命周期实例: Life 1      │  │   短生命周期实例: Life 2      │
       │   - 负责: 模块A开发 (串行S01~16) │  │   - 负责: 模块B开发 (串行S01~16) │
       │   - 提交原子回执后即刻消亡!    │  │   - 提交原子回执后即刻消亡!    │
       └───────────────────────────────┘  └───────────────────────────────┘
```

### 1. Agent PP（单例并发中枢 · Parallel Processing Orchestrator）
- **单例铁律 (Singleton Law)**：在单个任务会话的全生命周期中，**Agent PP 始终唯一存在**，绝对禁止多重实例化；
- **职责边界**：
  1. **管并发**：负责把复合任务拆解为独立的并行分支；
  2. **调生命周期**：根据子任务需要，动态派生 `life1`、`life2`、`life3`...；
  3. **汇聚屏障 (Join Barrier)**：监听所有派生出来的 `life(N)` 汇报，汇聚全部成果；
  4. **结项初始化 (Teardown)**：全部子任务完成后，清空所有 life 实例，全局状态完全重置归零。

### 2. Agent Life(N)（短生命周期串行执行体 · Ephemeral Sequential Executor）
- **多实例多命名**：按照 `life1`、`life2`、`life3` 顺序递增编号，其绑定的子任务 ID 在该任务中唯一；
- **管串行**：单个 `life` 实例内部**坚决禁止随意分叉**，严格按照标准工序单线串行推进；
- **调用即消亡 (Ephemeral Lifecycle)**：
  - 子任务完成并向 `Agent PP` 成功递交原子回执后，该 `life(N)` 实例立即置为 `TERMINATED` 并销毁；
  - 彻底释放其申请的内存、锁与中间句柄，绝不常驻堆积。

## 🔄 二、PP 调度 Life 的四步标准流水线

1. **【析】(拓扑拆解)**：PP 分析任务输入，识别相互无数据依赖的独立模块，生成分支清单；
2. **【派】(动态派生)**：PP 针对每个独立分支分别拉起 `life1`, `life2`...，指定各自负责的目标；
3. **【收】(原子汇聚)**：各 `life(N)` 串行执行完毕后出具 `Stage Receipt` 上报 PP，随后自我销毁；
4. **【合】(结项入库)**：PP 汇集全部分支成果，统一触发 G1~G4 全量门禁校验与 Git 提交推送，并调用 `--reset` 初始化全部临时状态。
