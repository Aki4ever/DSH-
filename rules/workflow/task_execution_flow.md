# 任务执行结构化流程与极简图形交互规范 (Task Execution Flow & Visual Standards)

本文档是工程内所有任务执行的最高实操指引，规范了**六步闭环流程**、**快慢双轨分流管道**、**任务分类编码体系**、**100 分制难度量化打分模型**、**8 字标题硬性限制**、**首轮定标自动重命名机制**、**极简轻量图形提示符**以及**吸附置顶组件**标准。

---

## 🧭 一、核心理念与快慢双轨分流管道

为了兼顾“大任务严密可控”与“小任务敏捷高效”，系统确立**快慢双轨分流执行管道**：

```text
                  ┌── [难度 ≤ 35分 · 轻量] ──▶ 快速轻量流 (Fast Track) ──▶ 【探】➔【攻】➔【归】
[用户输入新任务] ──┤
                  └── [难度 > 35分 · 复杂] ──▶ 标准完备流 (Standard Track) ──▶ 标准六步闭环流
```

### 1. 快速轻量流 (Fast Track · 难度 ≤ 35分)
- **适用场景**：单点文字微调、单文件读取问答、环境参数核验、无害化快速巡检；
- **轻量三步**：
  1. **【探】(探查)**：快速感知目标文件或状态；
  2. **【攻】(落地)**：精准给出结论或微调内容；
  3. **【归】(归卷)**：通俗说明结果，必要时顺带提交。
- **免除项**：无需冗长图形进度条、无需拆分复杂多层 Todo、无需强制吸顶置顶。

### 2. 标准完备流 (Standard Track · 难度 > 35分)
- **适用场景**：新增/修改核心规则、跨文件架构重构、功能/脚本研发、安全敏感操作；
- **标准六步闭环**：
  $$\text{【探境】(探)} \longrightarrow \text{【定标】(定)} \longrightarrow \text{【筹策】(筹)} \longrightarrow \text{【攻坚】(攻)} \longrightarrow \text{【质检】(验)} \longrightarrow \text{【归卷】(归)}$$
- **强制项**：首轮定标即刻执行会话重命名、开启吸顶置顶卡片、双向回写需求台账、Git 语义化提交。

## ⚙️ 二、细化标准六阶十六步固化流水线 (Strict 16-Step Pipeline)

为防止智能体产生“脑内跳步、忽略重命名、无回执盲动”的问题，将标准流固化为**十六道不可拆解、不可跳跃的严密工序**：

| 阶段 | 工序号 | 工序名称与核心动作 | 输入依据与工具 | 强制门禁与交付证据 (必须显式输出) |
| :--- | :---: | :--- | :--- | :--- |
| **一、探境** | **S01** | **环境权限与安全自检** | 读取环境变量与安全法典 | 输出沙箱模式、免审批状态与安全红线备忘 |
| | **S02** | **干道路由与业务基线检索** | 命中 G0/G1 干道，查知识库 | 声明意图干道，核对业务法典防冲突依据 |
| **二、定标** | **S03** | **需求意图提炼与查重** | 检索需求台账历史条目 | 输出结构化意图分析与查重拦截结论 |
| | **S04** | **双螺旋决策打分** | 价值60分模型 + 难度100分模型 | 输出价值分、难度分、轨道分流与分类代号 |
| | **S05** | **首动握手重命名门禁** | 执行 `./scripts/rename_session.sh` | **必须作为首个工具调用！** 输出重命名成功回执 |
| | **S06** | **视口置顶核心工单确立** | 提炼核心交付与边界 | 输出 Sticky 置顶核心工单卡片 |
| **三、筹策** | **S07** | **步骤拆解与 Todo 清单初始化** | 调用 `todo_write` 工具 | 建立全生命周期任务列表（单一在办事项） |
| | **S08** | **原子事务边界与回滚预案** | 评估可能影响的文件范围 | 圈定修改边界，制定异常回滚方案 |
| **四、攻坚** | **S09** | **前置指纹单次读取 (按需)** | 调用 `read` 工具 | 同一文件按指纹只读一次，避免无故复读 |
| | **S10** | **精准原子化编写与修改** | 调用 `write` / `edit` / `bash` | 严禁暴力大面积覆盖，确保资产与元数据成对修改 |
| | **S11** | **写后强制读回校验 (Read-Back)** | 调用 `read` 工具读回已修改内容 | **写后必读回！** 验证语法与结构完整性 |
| **五、质检** | **S12** | **工程与脚本功能真实跑通** | 执行命令或校验脚本 | 输出实操命令运行结果，杜绝假设性通过 |
| | **S13** | **关联存量文件联动排查** | 检索工程内文档/链接引用 | 消除死链、冲突或旧版本号遗留 |
| **六、归卷** | **S14** | **版本号同步与需求台账回写** | 修改 `docs/requirements.md` 等 | 实施版本号严格同生共死推进 |
| | **S15** | **Git 语义化提交与远程推送** | 执行 `git commit` & `git push` | 输出远程推送回执与 Commit-Hash 溯源码 |
| | **S16** | **交付入口呈现与效率审计结算** | 输出直达入口与审计看板 | **必给直达卡片 + 输出 M1~M6 效率量化审计看板** |

## 🏷️ 三、任务分类编码与命名规约 (强制规范)

### 1. 分类编码体系 (字母/中文单字 + 三位数字)
所有任务均按业务领域归入以下六大类别，字母与中文等价：

| 字母代号 | 中文代号 | 分类全称 | 涵盖范畴 | 编号示例 |
| :---: | :---: | :--- | :--- | :--- |
| **R** | **规** | **规则协同类 (Rule)** | 系统元规则、协同工作流、命名规范、交互协议 | `R001` / `规001` |
| **F** | **功** | **功能研发类 (Feature)** | 业务代码实现、功能研发、自动化脚本开发 | `F001` / `功001` |
| **D** | **文** | **文档知识类 (Doc)** | 教学图解、搜索引擎框架类比映射、使用指南 | `D001` / `文001` |
| **S** | **系** | **系统配置类 (System)** | 宿主 settings 配置、多模态支持、环境依赖 | `S001` / `系001` |
| **O** | **运** | **运维治理类 (Ops)** | 仓库初始化、Git 提交推送、存量回溯重命名 | `O001` / `运001` |
| **Q** | **测** | **质检核验类 (QA)** | 规则冲突体检、语法检查、死链排查、合规校验 | `Q001` / `测001` |

### 2. 双螺旋量化决策模型：六维价值打分 (60分) + 四维难度打分 (100分)

系统采取**价值评估**（判断值不值得做、收益几何）与**难度评估**（判断成本复杂度、分流轨道）双螺旋决策：

#### (1) 六维需求价值评分模型 (总分 60 分 · 各项 10 分)
所有任务在定标阶段，优先对需求本身进行价值六维量化：
1. **战略契合度 (0~10分)**：是否符合工程最高元规则与主线规划；
2. **效率增益度 (0~10分)**：对日常运转、开发交付效率的提振幅度；
3. **变现可行性与商业回报 (0~10分)**：对商业化落地、产品变现或直接ROI的支撑潜力；
4. **复用与扩展性 (0~10分)**：是否具备跨场景横向扩展与生态适配能力；
5. **痛点急迫度 (0~10分)**：解决阻断性Bug、流程瓶颈或不可逆漏洞的紧急程度；
6. **体验与透明度 (0~10分)**：对交互直观性、可解释性与容错性的改善程度。

- **价值等级**：
  - **[50~60分·核心战略级]**：高回报核心需求，优先分配全资源攻坚；
  - **[35~49分·高价值优化级]**：稳步推进，标准闭环；
  - **[0~34分·边缘低频级]**：精简范围，避免过度设计。

#### (2) 100 分制难度量化打分模型 (100分最难)
杜绝主观定级，通过四维客观指标加权计算出 0~100 分：
$$\text{难度总分} = \text{影响范围}(0\sim30) + \text{依赖深度}(0\sim30) + \text{安全风险}(0\sim20) + \text{技术复杂度}(0\sim20)$$

- **影响范围 (0~30分)**：单文件微调 (5~10分) ｜ 模块多文件 (15~20分) ｜ 全局架构调整 (25~30分)
- **依赖深度 (0~30分)**：无外部依赖 (5~10分) ｜ 模块上下游联动 (15~20分) ｜ 跨系统/宿主基座联动 (25~30分)
- **安全风险 (0~20分)**：低风险可即时回滚 (5分) ｜ 中等风险需校验 (10~15分) ｜ 不可逆/高危改动 (20分)
- **技术复杂度 (0~20分)**：纯文本/文档说明 (5分) ｜ 标准逻辑 (10~15分) ｜ 复合架构/深度优化 (20分)

#### 难度分级与轨道映射
- **[85~100分·极高]**：标准完备流（核心元规则重大重构、灾难性故障恢复）
- **[65~84分·高难]**：标准完备流（多模块全量联动治理、宿主底层能力深度改造）
- **[35~64分·中等]**：标准完备流（新增核心规范文件、常规功能研发与扩展）
- **[0~34分·轻量]**：**快速轻量流**（局部文字润色、单点文件微调、无害化巡检）

### 3. 任务概述字数限制（≤ 8 个汉字）
为防止侧边栏排版拥挤与文字截断，会话与任务栏统一命名格式强制为：
$$\mathbf{[分类编号][难度分]\ 8字以内概述}$$

- **合规示例**：
  - `[O001][60分] 工程初始化与Git` (8字)
  - `[D001][45分] DSH能力体系梳理` (8字)
  - `[R001][70分] 谷歌引擎类比模型` (8字)
  - `[R002][65分] 任务流程规范化` (7字)
  - `[S001][55分] 开启图片浏览能力` (8字)
  - `[R003][70分] 全局体系升级工单` (8字)

## 🔄 四、会话命名自动化与触发契约 (防漏机制)

为彻底解决前端默认抓取首句导致侧边栏未规范命名的痛点，确立两道防线与一键调用工具：

### 1. 第一道防线：首轮【定标】即刻触发重命名
智能体在接收新任务的第一轮回复中，完成意图解析与难度打分后，**必须立即调用重命名机制锁定会话名称**，杜绝拖延到最后才改名。

### 2. 第二道防线：收尾【归卷】二次校准
在收尾归卷前，智能体核对当前会话名称，若未符合 8 字规范则立即纠正。

### 3. 一键调用标准工具
工程提供统一的自动化脚本：
```bash
./scripts/rename_session.sh "[分类编号][难度分] 8字概述"
```
脚本自动解析当前环境 `$DSH_SESSION_ID` 与 `$DSH_WEB_URL`，向 DSH 后端发送标准的 `session.rename` RPC 指令并核验返回值。

## 🛡️ 七、高效执行防护与资源调度守则 (Execution Safeguards)

为保障模型在 DSH 宿主环境下的长效运行与精准调度，确立以下硬性执行铁律：

### 1. 首动握手重命名门禁 (First-Action Handshake Gate)
- **绝对前置**：接收到新任务进入【定标】阶段后，发出的**第一个 bash 工具调用必须且必定是 `./scripts/rename_session.sh "[分类编号][难度分] 8字概述"`**；
- **阻塞性红线**：未执行该命令前，严禁下发任何代码或业务文档的写操作；收尾归卷二次校验，彻底杜绝侧边栏标题丢失。

### 2. 上下文指纹单次读取原则 (Idempotent Read)
- **零冗余读取**：在同一个任务步骤内，对于未发生变更的同一文件路径，依据内容哈希指纹仅允许读取一次；
- **重读合法触发点**：仅在文件被写入修改后（写后读回校验）、外部进程产生物理变更、或需探查新范围时，才可再次执行读取并显式说明原因，最大程度节省上下文 Token 预算。

### 2. 两步无进展留证熔断与状态恢复 (Circuit Breaker)
- **熔断阈值**：若同一目标连续经历两次工具调用/指令尝试仍无实质进展（报错循环、无新信息增量），或达到单步算力预算上限时，**必须强制触发熔断机制，严禁无休止盲目重试**；
- **留证与恢复**：立即留存当前上下文与完整错误证据，阻断当前失败路径，并回退至上一个已知安全、已完成验证的稳定检查点恢复执行。

### 3. 原生 Goal 胶囊动态分段与生命周期管理
- **原生胶囊调用**：面对跨多轮次自主演进的长生命周期任务、或用户明确要求时，必须使用 DSH 原生 `create_goal` 创建胶囊，并通过 `get_goal` / `update_goal` 维护生命周期；
- **动态分段保存**：每个阶段动态持久化：当前计划（Plan）、在办工作（Work Done）、验证证据（Evidence）与下一步动作（Next Step），确保跨轮次上下文无损衔接。

### 4. 强一致读回与原子提交
- 关键状态、配置文件与核心代码变更，严格遵守“先读后改、写后读回核对、原子闭环提交”；
- 避免模糊臆测结果，每次完成步骤必须留存真实执行回执与确定性结果。
