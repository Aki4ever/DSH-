## 🚦 一、执行双轨分层与判定准则

```text
                       ┌── [难度 ≤ 35分 · 满足捷径条件] ──▶ ⚡ 敏捷捷径通道 (Fast Track)
[输入新任务] ── 意图与打分 ──┤
                       └── [难度 > 35分 · 触碰任一红线] ──▶ 🚨 强制硬约束流 (Hard Line)
```

### 1. 强制必走流程 vs 捷径通道对照矩阵

| 执行环节 | 🚨 强制硬约束流程 (Hard Line) | ⚡ 敏捷捷径通道 (Fast Track) |
| :--- | :--- | :--- |
| **触发门槛** | 难度 $> 35$ 分；或触及跨模块重构、核心规则修改、代码新增、发布升版 | 难度 $\le 35$ 分；纯信息检索、单文件局部微调、文字修正、无害巡检 |
| **1. 会话重命名** | **必须首发调用** `./scripts/rename_session.sh` 锁定 8 字以内标题 | **豁免**：直接沿用当前会话标题，无需首发改名 |
| **2. 知识库前置审查** | 强制检索 `knowledge/` 与元规则防冲突，遇冲突立即阻断 | **豁免**：纯技术或格式查询直接作答，免业务审查 |
| **3. 前置风险评估** | **必须显式输出**《前置四维风险评估卡》与回滚预案 | **捷径**：免输出独立大表格，以行内 1 句简述风险与防御 |
| **4. Todo 状态跟踪** | **必须调用** `todo_write` 激活原生 `TodoPanel` 状态条 | **捷径**：单步或简单双步任务免调用 `todo_write` |
| **5. 写后读回校验** | 凡写必读，修改后必须 `read` 读回确认完整性 | 保持一致（修改文件必读回校验，禁止盲目交付） |
| **6. 自动化测试门禁** | **必须编写/运行真实测试脚本**，100% 绿灯方可结项 | **捷径**：纯文档/配置微调，通过终端命令或读回校验即算通过 |
| **7. 页面台账与截图** | 涉及 Web/GUI 变动，强制截图并登记 `Page_*.png` 资产台账 | 非 GUI 前端任务与纯规则任务，完全免除截图与台账 |
| **8. 需求台账与升版** | **三位一体原子同步**：更新 `docs/requirements.md` 并推进版本号 | **捷径**：纯答疑、无实际文件持久化修改的任务免写台账 |
| **9. 收尾复盘与看板** | 强制输出三维 AAR 复盘卡与 M1~M6 效率审计指标看板 | **捷径**：免冗长 AAR 复盘与六维看板，输出精简交付总结 |

## ⚙️ 二、强制硬约束流程：标准六阶十六步流水线

当任务判定为 **Hard Line** 时，必须严格依序执行以下十六道工序，禁止脑内跳步：

| 阶段 | 工序号 | 工序名称与核心动作 | 输入工具 | 强制门禁输出 (必须显式呈现) |
| :---: | :---: | :--- | :--- | :--- |
| **一、探境** | **S01** | **环境权限与步骤全中文自检** | 环境变量读取 | 输出沙箱模式、安全红线与 Assistant 全生命周期纯中文说明声明 (工具 description 100% 规范汉化) |
| | **S02** | **干道路由与业务基线检索** | `knowledge/` | 声明命中干道（G0~G3），确认业务与世界观防冲突依据 |
| **二、定标** | **S03** | **需求意图提炼与查重** | `docs/requirements.md` | 提炼任务意图，比对历史台账杜绝重复创建 |
| | **S04** | **双螺旋决策打分** | 价值60分 + 难度100分 | 输出价值分、难度分、轨道判定（Hard Line / Fast Track） |
| | **S05** | **首动握手重命名门禁** | `./scripts/rename_session.sh` | **必须作为第一个 bash 工具调用！** 锁定 8 字标题 |
| | **S06** | **核心工单与立项赋能确立** | GFM 引用块 / 模板 | 输出置顶工单卡；新项目必须附带《项目 DSH 赋能规划卡》 |
| **三、筹策** | **S07** | **任务分解与 Todo 初始化** | `todo_write` | **激活输入坞 TodoPanel！** 维护 pending/in_progress 状态 |
| | **S08** | **风险揭示与全局资源防冲突锁定** | `global_scheduler_lock.sh` | **写前必控险与申领独占锁！** 遇资源冲突自动串行避让，防多任务打架 |
| **四、攻坚** | **S09** | **上下文指纹单次读取** | `read` | **激活 ReadCard！** 同一文件按指纹仅读一次 |
| | **S10** | **精准修改与遇碰即对齐** | `write` / `edit` | **激活 DiffCard！** 触碰存量旧文件时顺带升级至最新基线规范 |
| | **S11** | **写后强制读回与指纹校验** | `read` / 脚本 | **写后必读回！** 校验语法与指纹，杜绝未记录的漂移 |
| **五、质检** | **S12** | **自动化测试与质量门禁** | 测试用例与脚本 | **激活 TerminalCard！** 100% 绿灯，未测或报错严禁交付 |
| | **S13** | **存量排查与指纹台账同步** | `fingerprint_audit.sh` | 激活 SearchCard，消除死链；运行指纹更新维护新鲜度台账 |
| **六、归卷** | **S14** | **三位一体版本号强同步** | 需求台账与规则文档 | 严格同步 `docs/requirements.md`、知识库与实施版本 |
| | **S15** | **远程 Git 强同步与释放排他锁** | `git_sync_remote.sh` | **必须推送到远端并释放锁！** 无地址自动开页引导，未推禁言交付 |
| | **S16** | **可点击交付与 AAR 复盘** | 直达组件 + 内联代码 | **激活 turnTail 产出文件链接**，输出直达卡、Git 回执与 AAR |

## ⚡ 四、敏捷捷径通道：极简三步流

当任务判定为 **Fast Track** 时，执行极简三步闭环：
1. **【探】(快速感知)**：通过 `read` 或 `grep` 定位目标，激活 ReadCard，行内确认无高危风险；
2. **【攻】(精准落地)**：通过 `edit` 激活 DiffCard 进行最小粒度修改，紧随 `read` 读回确认；
3. **【归】(精炼交付)**：输出结构化交付说明与可点击链接，跳过冗长看板，快速响应。

## 🏷️ 五、任务打分与命名规范

### 1. 100 分制难度打分模型
$$\text{难度总分} = \text{影响范围}(0\sim30) + \text{依赖深度}(0\sim30) + \text{安全风险}(0\sim20) + \text{技术复杂度}(0\sim20)$$
- **[35~100分]**：自动进入 **Hard Line** 强制完备流；
- **[0~34分]**：自动进入 **Fast Track** 敏捷捷径通道。

### 2. 会话命名格式（≤ 8 汉字）
格式强制为：`[分类编号][难度分] 8字概述`
- 示例：`[R001][60分] 任务流程重构` (8字) ｜ `[O002][25分] 磁盘周期清理` (8字)

## 🛡️ 六、执行安全与防死循环铁律

1. **两步无进展熔断 (Circuit Breaker)**：若同一错误连续尝试两次无增量，必须立即阻断并报错，禁止盲目反复重试；
2. **绝对白名单保护**：执行任何清理或批量修改时，`knowledge/`、`memory/`、`rules/`、`indexes/`、`docs/` 核心资产绝对禁止删除；
3. **GFM 原生组件规范**：禁止输出裸 HTML 标签，一律使用标准 Markdown 引用块（`>`）与表格呈现视觉卡片。
