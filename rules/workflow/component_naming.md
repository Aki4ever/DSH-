# 标准组件与 DSH 系统命名规范 (Component Naming Standard)

为了在人机协作和多智能体编排中实现高效、统一的指代与操作，制定本命名标准。

---

## 🛠️ 一、标准交互组件命名（日常操作指代）

| 模块分类 | 推荐指代简称 | 系统工具 ID | 核心职能 |
| :--- | :--- | :--- | :--- |
| **执行与终端** | **【终端执行】** | `bash` / `terminal` | 执行 Shell 命令与环境调试 |
| **异步作业** | **【后台任务】** | `job_list` / `job_output` / `job_kill` | 守护进程与长效作业监控管理 |
| **文件读写** | **【文件查看】** | `read` | 安全按行分片读取文本 |
| | **【文件写入】** | `write` | 全新建立或全量覆写文件 |
| | **【精准编辑】** | `edit` | 基于文本匹配的精准增量修改 |
| **文件检索** | **【路径搜索】** | `glob` | 跨层级多模式文件路径检索 |
| | **【代码检索】** | `grep` | 基于 ripgrep 正则的内容快速检索 |
| **视觉多模态** | **【图像解析】** | `read_image` | 读取多模态图片文件 |
| **联网搜索** | **【联网检索】** | `web_search` | 获取互联网最新信息与技术资料 |
| **进度规划** | **【任务看板】** | `todo_write` | 维护结构化多步骤任务状态 |
| | **【规划模式】** | `exit_plan_mode` | 规划方案制定与人机确认批准 |
| **自主闭环** | **【自主目标】** | `create_goal` / `get_goal` / `update_goal` | 多轮连续自治的长效目标驱动 |
| | **【自愈循环】** | `ralph` | 无状态快速 fresh-agent 自愈迭代 |
| **多智能体** | **【子智能体】** | `subagent` / `subagent_fork` | 独立上下文子代理任务分派 |
| | **【智能体总线】** | `list_agents` / `send_message` / `interrupt_agent` | 子代理监控、通讯与生命周期管控 |
| | **【工作流编排】** | `workflow` | 基于 JS 脚本的大规模并发与流水线编排 |
| **协同交互** | **【人机确认】** | `ask_user_question` | 关键分支与多选决策弹窗确认 |
| **扩展技能** | **【动态技能】** | `skill` | 按需挂载特定垂直领域的专家能力 |

## 🏛️ 二、DSH 核心系统架构命名

| 架构层级 | 推荐中文代号 | 架构包名标识 |
| :--- | :--- | :--- |
| **启动底座** | **DSH 基座引擎** / **容器框架** | `dsh-base` / `cordis` |
| **安全沙箱** | **文件沙箱** / **终端沙箱** | `dsh-fs-sandbox` / `dsh-bash-sandbox` |
| **模型调度** | **大模型网关** / **DeepSeek 直连器** | `dsh-llm` / `dsh-llm-deepseek` |
| **会话状态** | **会话状态存储** / **历史修剪器** | `dsh-session` / `dsh-compaction` |
| **图形前端** | **Web GUI 界面** / **工作区管理器** | `dsh-web-app` / `dsh-workspace` |
