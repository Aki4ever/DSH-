---

## 🚫 一、绝对阻断的八大红线原语 (Absolute Redlines)

凡遇到以下八类操作，智能体必须**强制自我阻断**，不得盲目下发危险命令：

| 红线类别 | 高危场景示例 | 自主防护策略与动作 |
| :--- | :--- | :--- |
| **1. 根目录与宿主破坏** | `rm -rf /`、`rm -rf ~`、清除非工程外层目录 | **绝对阻断**。命令直接拒执，输出阻断警报。 |
| **2. 凭证与隐私泄露** | 读取或外发 `.env`、SSH 密钥、私有 Token、密码 | 仅支持在本地受控使用，严禁向外网络或对话泄露明文凭证。 |
| **3. 生产环境盲目部署** | 未经验证直接部署生产集群或覆盖生产数据库 | 必须前置通过完整本地质检与环境核对。 |
| **4. 历史篡改与强推** | `git push -f`、`git reset --hard` 回滚他人提交 | 严禁覆盖远程主分支历史，冲突时优先采用非破坏性合并。 |
| **5. 大面积非受控覆盖** | 正则暴力替换多文件或清空未经备份的目录 | 必须“先读后改、精准定位、保留历史快照”。 |
| **6. 破坏性文件删除** | 删除用户对话历史、任务台账或核心规则源文件 | 严禁物理硬删除，必须改用标记废弃或归档模式。 |
| **7. 盲目重发未明调用** | 网络超时或状态未知时立即换路重发写操作 | 遵循幂等原则，必须“先读回状态确认结果”，不明不重发。 |
| **8. 破坏 Unity 资产引用** | 单方面删除/移动 Unity 资产而遗漏 `.meta` 文件 | 必须与 `.meta` 文件成对原子操作，防止 GUID 断裂。 |

## 🛡️ 二、写后读回 (Read-Back) 与幂等验证机制

1. **写后强制读回**：
   - 凡修改系统元规则、关键配置文件（`settings.yaml`）或核心业务逻辑，修改完毕后必须执行 `read` 工具读回，核验格式完整无损；
2. **两步无进展熔断**：
   - 任何涉及排查、命令执行的操作，连续两次未取得正向进展，立即留存证据并熔断回退，严禁死循环消耗算力。

---

## 🚪 三、结构化输出入口必给铁律

在完成任何涉及系统配置、脚本生成、图表产出或 Web 服务的任务时，收尾必须提供直达入口：
- **Web 服务**：给出可直接点击的完整 URL；
- **图片/图表**：使用 Markdown 语法渲染预览并提供文件打开链接；
- **CLI/命令**：提供单行免配置的直接运行命令；
- **代码文件**：给出可点击的 Markdown 路径。
