## 🛠️ 一、技术基准与基础设施选型

| 技术维度 | 选型标准与基线版本 | 强制说明与约束 |
| :--- | :--- | :--- |
| **游戏引擎** | **Unity 2022.3 LTS (长期支持版)** | 统一团队引擎小版本，禁止个人擅自升级或降级引擎版本 |
| **渲染管线** | **通用渲染管线 (URP - Universal RP)** | 统一使用 Linear 色彩空间与 Single Pass 渲染路径 |
| **编程语言** | **C# 9.0 / .NET Standard 2.1** | 统一采用强类型安全风格，严禁使用非受控的反射黑魔法 |
| **资源管线** | **Addressables (可寻址资产系统)** | 彻底弃用 `Resources/` 目录动态加载，实现全量按需寻址与热更隔离 |
| **代码模块化** | **Assembly Definition Files (.asmdef)** | 按领域强制分包编译，杜绝单一大工程全局重编译 |

## 📊 二、性能预算与硬性指标红线 (Performance Budget)

以主流中端移动设备（如骁龙 778G / 苹果 A12 级别）为基准运行环境：

| 性能指标项 | 达标安全线 (Green) | 警告线 (Yellow) | 🚨 绝对阻断红线 (Red) |
| :--- | :---: | :---: | :---: |
| **目标帧率 (FPS)** | 稳定 60 FPS | 45 ~ 59 FPS | **< 45 FPS (直接卡顿打回)** |
| **DrawCall (批次)** | ≤ 120 次 | 120 ~ 180 次 | **> 200 次** |
| **SetPass Calls** | ≤ 30 次 | 30 ~ 50 次 | **> 60 次** |
| **同屏总三角面数** | ≤ 250,000 面 | 250,000 ~ 400,000 面 | **> 500,000 面** |
| **Managed Mono 堆内存** | ≤ 120 MB | 120 ~ 200 MB | **> 250 MB** |
| **帧级 GC 垃圾产生量** | **0 B/frame** (平稳运行期) | < 500 B/frame | **> 1 KB/frame (Update内严禁)** |
| **APP 初始启动耗时** | ≤ 3.0 秒 | 3.0 ~ 5.0 秒 | **> 6.0 秒** |

## 🏗️ 三、架构分层与设计规范

统一推行 **MVVM / MVP** 逻辑与表现彻底解耦架构：

```text
┌────────────────────────────────────────────────────────┐
│             View 表现层 (MonoBehaviour / UI / 特效)     │
│   - 只负责视觉渲染、动画播放、声音播放、用户输入事件收集  │
└───────────────────────────▲────────────────────────────┘
                            │ 严格单向监听 / 事件回调 (无双向依赖)
┌───────────────────────────▼────────────────────────────┐
│            Presenter / Controller 业务调度层           │
│   - 负责业务逻辑判定、状态机调度、UI 与数据间的胶水同步 │
└───────────────────────────▲────────────────────────────┘
                            │ 纯逻辑接口调用
┌───────────────────────────▼────────────────────────────┐
│              Model / Data 核心数据层 (纯 C# POCO)       │
│   - 纯数据结构、网络协议包、本地配置缓存、完全脱离 UnityEngine│
└────────────────────────────────────────────────────────┘
```

1. **核心逻辑去 MonoBehaviour 化**：
   - 纯粹的数学计算、算法、数据实体与网络层禁止继承 `MonoBehaviour`；
   - 只有真正需要挂载在 GameObject 上参与 Unity 渲染管线、物理碰撞或输入响应的组件才允许继承。
2. **事件驱动与消息解耦**：
   - 跨模块通信统一走强类型轻量消息事件总线（EventBus），严禁跨模块强引用对方的内部私有实现。
3. **单例模式 (Singleton) 严格受控**：
   - 严禁每个管理器都写成公开静态全局单例；
   - 全工程全局单例限制在 3 个以内（如 `GameApp`、`AudioService`、`NetworkService`），其余模块统一依赖注入或由主上下文托管。

## ⚡ 四、内存与 GC 零压力运行准则

1. **零 GC 垃圾回收法则**：
   - 严禁在 `Update()`、`LateUpdate()`、`FixedUpdate()` 高频轮询生命周期内执行任何 `new` 操作；
   - 严禁在高频函数中使用字符串拼接（`str1 + str2`），统一预分配 `StringBuilder` 或使用缓存 ID；
   - 字符串到数值比较必须使用 Hash 映射（如 `Animator.StringToHash`、`Shader.PropertyToID`）；
   - 列表查询严禁使用 LINQ（LINQ 每次调用都会产生迭代器闭包对象与 GC 垃圾）。
2. **对象池 (Object Pool) 强制应用**：
   - 子弹、粒子特效、伤害漂字、同屏小怪、常用音效等高频复用实体，必须接入对象池机制，杜绝频繁 `Instantiate()` 与 `Destroy()`。

## 🚫 五、工程审查冲突阻断红线 (前置阻断)

在新需求代码评审或功能设计实施前，若违反以下任一红线，**前置核验必须立刻阻断**：
1. **主线程卡顿阻断**：严禁在 Unity 主线程执行同步阻塞式的耗时 IO 操作（如大文件同步读取、阻塞式网络连接、未异步化的复杂解压缩）；
2. **循环依赖阻断**：禁止不同程序集之间出现互引双向循环依赖（必须提取公共接口或数据层单向依赖）；
3. **内存泄漏阻断**：任何注册了全局事件监听的对象，在自身销毁时（`OnDestroy` / `Dispose`）必须显式注销，否则视为致命内存泄漏风险；
4. **硬编码污染阻断**：严禁在业务代码中硬编码文件系统绝对物理路径（如 `/Users/...` 或 `D:\...`），必须统一通过 Unity 标准 API（`Application.persistentDataPath` 等）或配置中心解析。
