# 知识来源登记层 (Knowledge Sources Registry)

> **本层性质**：知识库的**出处登记目录**，不承载任何工程条款。
> **规范层级**：`【知识库第三层 · 来源出处登记】`
> **需求依据**：`REQ-089`（GCM-ORCH）之 R1-a 子项。
> **对应实施版本**：`v4.24.0`（REQ-089 实施中；完成后递增至 `v4.25.0`）。
> **生效状态**：`[Release 稳定生效]`

本层解决一个此前长期缺失的问题：**知识库里有"提取后的规则"，却没有"规则是从哪本书、哪篇文献来的"。**

结果是两条隐患：
1. 规则一旦与原文冲突，**无法回溯核对**——没有任何锚点能指出"这条规则对应原书哪一章"；
2. 引用时容易**把二手转述当原典**，甚至凭空给某条规则编一个出处。

---

## 📌 一、本层定位与边界

| 维度 | 本层管什么 | 本层**不**管什么 |
| :--- | :--- | :--- |
| 对象 | **原始出处**：书目、文献、版次、权威章节、引用锚点 | 规则条款本身（那是 `knowledge/common/` 的事） |
| 作用 | 为每条规范条款提供**可回溯的出处锚点**与**元数据核验状态** | 复述规则内容 |
| 权威关系 | **来源层是"出处"的唯一权威**；规范层是"条款"的唯一权威 | 二者不得互相复述对方的正文 |

## 🛠️ 三、新增来源的登记规约

1. **一源一卡**：每个来源一个 `SOURCE-<三位编号>-<语义化英文短名>.md`，禁止把两个来源塞进同一张卡；
2. **必须有真实出处**：作者、标题、年份、出版方（或期刊/卷期）四要素齐全，缺一不予登记；
3. **必须标注核验状态**：未逐页核对的一律 🟡，禁止直接标 🟢；
4. **必须写引用锚点**：明确"本工程哪份规范的哪一节由本来源支撑"，便于双向寻址；
5. **与规范层单向解耦**：来源卡**只写出处与要点索引**，不复述工程条款；规范文件**只写条款**，出处一律指向本层。

## 🔗 四、双向寻址

```text
规范条款  ──引用──▶  knowledge/sources/SOURCE-00X        （条款说"依据见来源卡"）
来源卡    ──索引──▶  knowledge/common/*.md 的具体章节    （来源卡说"支撑了哪一节"）
```

- 索引层指针：[`indexes/rules_index.md`](../../indexes/rules_index.md)（知识库分层表）；
- 知识库总索引：[`knowledge/README.md`](../README.md)（目录拓扑）。

---

## 🛠️ 维护原则
- 遵循 [`rules/system/meta_rules.md`](../../rules/system/meta_rules.md) 最高准则；
- 来源卡内容一旦修订必须同步更新本表的"被引用位置"列，防止单向断链；
- **新增来源必须先在 `indexes/rules_index.md` 的知识库分层表里挂上指针**，再写卡；
- 来源卡与规范文件之间只允许"指针关系"：来源卡不写工程条款，规范文件不写出版信息；
- 保持文档全中文、通俗直白、无生僻字。
