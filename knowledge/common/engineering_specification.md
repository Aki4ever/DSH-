## 🏗️ 一、模块分层与单向依赖原则 (Layering & Decoupling)

所有工程代码与架构设计，必须遵循严格的四层单向依赖模型：

```text
┌────────────────────────────────────────────────────────┐
│ 1. 表现展示层 (Presentation / UI / Pages / Dialogs)   │
└───────────────────────────┬────────────────────────────┘
                            │ 单向调用，严禁逆向回环
                            ▼
┌────────────────────────────────────────────────────────┐
│ 2. 业务应用层 (Application / ViewModels / Controllers) │
└───────────────────────────┬────────────────────────────┘
                            │ 单向调用
                            ▼
┌────────────────────────────────────────────────────────┐
│ 3. 领域核心层 (Domain Core / Models / State Machine)   │
└───────────────────────────┬────────────────────────────┘
                            │ 依赖倒置 / 接口契约
                            ▼
┌────────────────────────────────────────────────────────┐
│ 4. 基础实施层 (Infrastructure / Network / Storage)     │
└────────────────────────────────────────────────────────┘
```

1. **零回环依赖 (No Circular Dependency)**：底层逻辑模块绝对禁止引用上层 UI 具体组件；
2. **状态机原子性 (Atomic FSM)**：涉及状态转移的业务逻辑（战斗状态、购买流程、认证流程），状态流转必须设计为不可分割的有限状态机，中途失败必须完整回退至上一稳定态。

## ⚡ 二、运行期性能与零 GC 内存管理

1. **帧循环零分配 (Zero-Allocation in Loops)**：
   - 严禁在 `Update()`, `requestAnimationFrame()`, `onPageScroll()` 等高频逐帧函数中执行 `new` 对象、闭包分配或高频字符串拼接（使用 `StringBuilder` 或对象池）；
2. **对象池机制标配 (Object Pooling)**：
   - 凡高频创建销毁的实体（子弹、飘字、特效、动态列表项），必须纳入对象池统一复用，严禁高频执行 Instantiate/Destroy。

---

## 🛡️ 三、异常处理与三段式收敛

1. **异常捕获三原则**：
   - 不吞异常：禁止空的 `catch {}` 块；
   - 确定性回执：向调用方返回结构化 Result 对象或有明确意义的错误码；
   - 面向用户友好：底层原生堆栈必须通过三段式解析（中文释义、根本原因、修复建议）转化为人类可读的提示信息。
