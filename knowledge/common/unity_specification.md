# 通用 Unity 客户端工程规范 (General Unity Engineering Specification)

> ### 🏷️ **版本信息与实施追踪**
> - **当前文档版本**：`v4.6.0`
> - **对应实施版本**：`v4.6.0`
> - **规范层级**：`【知识库总纲 · 通用公共规范】`（所有 Unity 项目 100% 共享继承）
> - **生效状态**：`[Release 稳定生效]`

本文档是系统所有 Unity 游戏与客户端工程的**最高通用实操规范**。无论处于哪个子项目，所有场景搭建、预制体拆分、UI 交互与底层代码编写必须细化遵循本法典。

---

## 🏗️ 一、场景与预制体边界铁律：页面做成 Scene，弹窗做成 Prefab

为确保内存受控、多人协作无冲突及性能最优，系统严禁在单一场景中堆叠全量 UI，确立**“页面为场景、弹窗为预制体”**的刚性工程边界：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Unity 视图与装配分层模型                        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 页面流转切换 (SceneManager 异步加载)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 🌍 【主视图 / 页面层】—— 必须做成独立 Scene (.unity)                   │
│    • 涵盖范围：登录页、主大厅页、关卡选择页、战斗场景页、角色养成主页    │
│    • 存放规范：Assets/_Project/Scenes/Pages/Scene_<PageName>.unity     │
│    • 优势：生命周期自闭环、内存加载卸载彻底、DrawCall 天然隔离           │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 交互唤起 (UIManager 动态按需实例化)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 🪟 【浮层 / 弹窗层】—— 必须做成独立 Prefab (.prefab)                   │
│    • 涵盖范围：提示对话框、背包详情窗、设置面板、结算卡片、二次确认框    │
│    • 存放规范：Assets/_Project/Prefabs/UI/Dialogs/Dlg_<Name>.prefab   │
│    • 优势：动态 Instantiate / Pool 回收、不占用场景启动常驻内存        │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 页面级规范 (Page as Scene)
- **独立 Scene 场景**：主导航切换的页面必须是独立 Scene，通过 `SceneManager.LoadSceneAsync` 或 Addressables 场景句柄加载；
- **场景轻量化**：Scene 内仅包含该页面独有的静态背景、三维机位、灯光环境及主 Canvas 框架；
- **禁止堆砌**：严禁在 Scene Hierarchy 根节点预先摆放未激活（`SetActive(false)`）的各类大型交互浮窗。

### 2. 弹窗级规范 (Popup as Prefab)
- **独立 Prefab 预制体**：所有弹窗、卡片式浮层、悬浮气泡统一做成独立 Prefab；
- **动态创建与销毁**：通过单例 `UIManager.Open<T>()` 动态挂载至专属的 `PopupCanvas` 下；
- **全屏暗色遮罩标配**：每个弹窗 Prefab 根节点必须自带半透明黑色遮罩层（Alpha `0.6`），阻止下层点击穿透并满足格式塔主体背景律。

## 🔘 二、按钮与交互组件实操规范：必须配置阴影与物理动效

系统严禁使用 Unity 原生白色无阴影的扁平按钮，所有可交互组件必须拥有细致到像素级的视觉反馈：

### 1. 按钮投影阴影 (Drop Shadow) 标配
所有 uGUI 按钮的背景底板（Image 组件），必须满足以下两者之一：
- **方案 A (挂载 Shadow 组件)**：
  - 必须挂载 Unity 原生 `UnityEngine.UI.Shadow` 组件；
  - **阴影位移 (Effect Distance)**：固定为 `(0, -3)` 或 `(1, -3)`（模拟上方光源向下投射）；
  - **阴影色彩 (Effect Color)**：`RGBA(0, 0, 0, 110)`（半透明炭黑，自然虚化边缘）；
  - **双重立体 (可选)**：针对主操作大按钮，可额外叠挂 `Outline` 组件，描边色彩 `RGBA(0, 0, 0, 40)`，描边厚度 `1px`。
- **方案 B (9-Sliced 精灵图自带内嵌投影)**：
  - 美术输出的切片贴图底部必须自带 `3~6px` 渐变暗调阴影槽。

### 2. 按钮四态交互微动效 (Four-State Transitions)
所有按钮组件必须在 Inspector 明确配置 `Transition` 模式：

| 交互状态 | 视觉与动画具体表现参数 | 听觉反馈 |
| :--- | :--- | :--- |
| **正常态 (Normal)** | 原始饱和度主色，阴影深度 `(0, -3)` | 无 |
| **悬停态 (Hover / Highlighted)** | 贴图亮度提升 `10%~15%`，外边框呈现微光外发光效果 | 弱按键滑过音 (Hover.wav) |
| **按压态 (Pressed)** | • **物理位移**：按钮内所有子元素（文本+图标）沿 Y 轴瞬时下移 `2px`；<br>• **缩放凹陷**：Scale 微缩至 `0.97`；<br>• **阴影收紧**：阴影位移减为 `(0, -1)`，模拟贴合地面真实机械感 | 清脆按键机械音 (Click.wav) |
| **禁用态 (Disabled)** | 按钮整体饱和度降为 0（变灰），Alpha 衰减至 `0.4`，阴影透明度衰减至 `0.2`，鼠标悬浮显示阻止态 | 禁用轻微蜂鸣音 (Disabled.wav) |

## ⚡ 三、Canvas 动静分离与层级渲染性能规范

1. **动静分离双 Canvas 架构**：
   - **Static Canvas**：放置背景底板、固定的边框栏、固定标题（零重绘，开启 Batching）；
   - **Dynamic Canvas**：放置频繁变动数值、血条跳动、飘字倒计时、跑马灯（发生局部重绘时绝不触发全屏 Canvas 重构）。
2. **Sorting Order 绝对层级字典**：
   - `Order 0 ~ 100`：Background & WorldSpace UI
   - `Order 100 ~ 500`：Page Normal UI（常规页面）
   - `Order 500 ~ 800`：Dialogs & Windows（二级弹窗）
   - `Order 800 ~ 950`：Top Alert & Toast（轻提示与二次防呆确认框）
   - `Order 950 ~ 999`：Global Loading & Transition Mask（全屏过场遮罩）

## 🔒 四、工程资产管理与 .meta 同生共死铁律

1. **.meta 严格对齐**：任何 Prefab、Scene、Texture、Script 新增、移动、重命名，必须与对应的 `.meta` 文件原子同步；
2. **asmdef 解耦**：UI 表现层代码（`_Project/Scripts/UI/`）必须单独建立 `UI.asmdef`，只单向依赖核心逻辑，严禁核心业务逆向依赖具体 UI 预制体。
