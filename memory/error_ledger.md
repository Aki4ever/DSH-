> ### 🏷️ **版本信息与实施追踪**
> - **当前文档版本**：`v4.10.0`
> - **对应实施版本**：`v4.10.0`
> - **管理职能**：记录任务执行过程中的典型报错、根因剖析与防复发对策
> - **生效状态**：`[Release 稳定生效]`

本文档是系统跨会话反思沉淀的核心载体。任何在任务执行中出现的非预期报错、构建异常或命令失败，均需提取特征、登记指纹并建立前置探针防复发对策，确保同类失误发生率持续收敛。

## 📋 一、报错登记标准结构模板

```markdown
### ERR-[编号]: [简明错误分类与特征]
- **登记时间**：YYYY-MM-DD
- **关联任务**：[分类编号][难度分] 任务概述
- **触发命令/工具**：例如 bash / edit / write
- **错误指纹 (Fingerprint)**：
  - 退出码或异常标识：Exit Code N / Error Type
  - 核心报错特征句：`[截取核心报错文本]`
- **三段式归因剖析**：
  1. **中文释义**：用通俗中文阐述系统在抱怨什么；
  2. **根本原因 (Root Cause)**：穿透分析为何前置假设失效；
  3. **本次修复路径**：本次如何排除障碍。
- **防复发对策与探针 (Anti-Recurrence)**：
  - 前置检查：未来执行该类动作前，必跑的探针命令；
  - 规则固化：是否已沉淀为门禁、自检清单或脚本硬断言。
- **复发状态**：🟢 未复发 / 🟡 曾复发已强化 / 🔴 待治理
```

## 🗂️ 二、典型高发报错模式与免踩坑速查

| 编号 | 报错模式 / 指纹 | 根本根因 | 刚性防复发探针 | 状态 |
| :--- | :--- | :--- | :--- | :---: |
| **ERR-001** | `No such file or directory` (写前未查或误假定父目录存在) | 在未确认上级目录存在的情况下直接创建深层路径文件 | 执行 `write` 前先用 `read` 或探测命令核实目录，必要时先建骨架 | 🟢 稳定 |
| **ERR-002** | `offset N is out of range` (大文件切片越界) | 凭借旧记忆或猜测行数下发 offset，未先通过工具或元信息掌握总行数 | 先以较小 offset 读取或通过小范围 grep 锁定关键锚点后定位 | 🟢 稳定 |
| **ERR-003** | `fatal: not a git repository` 或远程被拒 | 跨工程执行时工作目录与当前仓库环境漂移 | 统一使用绝对路径或在命令前显式校验 `git status` | 🟢 稳定 |
| **ERR-004** | `tool denied` / `sandbox escalation rejection` | 免审批环境下错误触发审批流或超出沙箱边界 | 遵守免审批白名单，禁止下发越界破坏性指令 | 🟢 稳定 |
| **ERR-005** | `bash: node: command not found [exit code: 127]` | 子shell缺少 Homebrew 或额外 bin 路径环境变量 | 执行前显式注入 `export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"` | 🟢 稳定 |

## 🔄 三、报错闭环工作流程规范

1. **遇错即停**：遇到命令非 0 退出，严禁原地无脑重试超过 2 次（触发两步熔断）；
2. **提取指纹**：提取命令报错核心句，在思维链中完成三段式解析；
3. **排查并落盘**：若该报错属工程共性问题或高频坑，登记至本台账；
4. **探针自进化**：将防范逻辑转化为脚本、门禁前置探测或 checklist，让后续任务在启动时“读记忆”自动避坑。
