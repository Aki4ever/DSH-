# 前置风险评估卡标准模板 (Risk Assessment Template)

> 规范遵循：[`rules/workflow/risk_disclosure.md`](../rules/workflow/risk_disclosure.md)  
> 使用时机：任务【三、筹策】阶段，动手修改任何业务代码或文件之前输出。

```markdown
### ⚠️ 前置风险评估与应对预案
- **技术/依赖风险**：[说明涉及的底层环境、第三方包、编译依赖或版本冲突隐患；若无变动填“经核验无三方依赖冲突”]
- **数据/破坏性风险**：[标明涉及覆盖/修改的文件范围、是否有不可逆删除、数据库迁移等操作]
- **需求边界风险**：[指出需求中存在的潜在歧义、对上下游其他模块的潜在耦合或侧漏影响]
- **降级与回滚方案**：[明确具体的回滚策略，如 Git commit 干净还原命令、本地备份恢复手段或功能降级方案]
```
